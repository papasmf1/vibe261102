## 1. 개요

### 1.1 배경
할 일 관리 앱은 많지만 대부분 기능이 과하거나 가입·동기화를 요구한다. 사용자는 **"오늘 해야 할 일"에만 집중**할 수 있는 가볍고 빠른 단일 페이지를 원한다.

### 1.2 목표
- 브라우저만 열면 바로 오늘의 할 일을 추가·완료·삭제할 수 있다.
- 새로고침하거나 브라우저를 다시 열어도 데이터가 유지된다.
- 설치·로그인·서버 없이 동작한다.

### 1.3 비목표 (Non-goals)
- 회원가입/로그인, 다중 기기 동기화
- 팀 협업, 공유 기능
- 장기 프로젝트 관리(간트 차트, 하위 작업 트리 등)
- 네이티브 모바일 앱

## 2. 대상 사용자 & 사용 시나리오

### 2.1 페르소나
- **직장인/학생**: 아침에 오늘 할 일을 3~10개 적고, 하루 동안 체크하며 진행 상황을 확인한다.

### 2.2 핵심 시나리오
1. 아침에 페이지를 열면 오늘 날짜와 함께 빈 목록(또는 어제 못 끝낸 일)이 보인다.
2. 입력창에 할 일을 입력하고 Enter로 추가한다.
3. 끝낸 일은 체크박스를 눌러 완료 처리한다 → 취소선 + 진행률 갱신.
4. 잘못 입력한 항목은 더블클릭해 수정하거나 삭제한다.
5. 다음 날 페이지를 열면 미완료 항목을 오늘로 가져올지 선택할 수 있다.

## 5. 화면 설계

### 5.1 레이아웃 (와이어프레임)

```
┌──────────────────────────────────────────┐
│  오늘의 할일                       [🌙]   │  ← 헤더 (제목, 다크모드 토글)
│  2026년 11월 2일 (월)                     │
├──────────────────────────────────────────┤
│  ┌ 어제 끝내지 못한 일 2개가 있어요 ──────┐ │  ← 이월 배너 (조건부, F-31)
│  │            [오늘로 가져오기] [무시]    │ │
│  └────────────────────────────────────────┘ │
├──────────────────────────────────────────┤
│  [ 할 일을 입력하세요...           ][추가] │  ← 입력 영역
├──────────────────────────────────────────┤
│  3 / 5 완료   ███████████░░░░░░░  60%     │  ← 진행률
│  [전체] [진행 중] [완료]                   │  ← 필터 탭
├──────────────────────────────────────────┤
│  ☐ ★ 기획서 검토하기                  ×  │
│  ☐   운동 30분                        ×  │  ← 할 일 목록
│  ☑   ~~이메일 답장~~                  ×  │
│  ☑   ~~장보기~~                       ×  │
│  ☑   ~~책 20쪽 읽기~~                 ×  │
├──────────────────────────────────────────┤
│                       [완료 항목 지우기]   │  ← 푸터
└──────────────────────────────────────────┘
```

### 5.2 상태별 화면
- **빈 상태**: 목록 영역에 일러스트/아이콘 + "오늘 할 일을 추가해 보세요"
- **편집 상태**: 해당 항목이 입력창으로 전환, 포커스 이동
- **삭제 직후**: 하단 토스트 "삭제됨 · [실행 취소]" (5초)
- **모두 완료**: 진행률 100% + "오늘 할 일을 모두 끝냈어요! 🎉"

### 5.3 인터랙션 / 단축키
| 동작 | 입력 |
|---|---|
| 추가 | 입력창에서 `Enter` |
| 입력창 포커스 | `/` 또는 `N` |
| 편집 시작 | 텍스트 더블클릭 / 항목 포커스 후 `Enter` |
| 편집 저장 / 취소 | `Enter` / `Esc` |
| 완료 토글 | 항목 포커스 후 `Space` |
| 삭제 | 항목 포커스 후 `Delete` |

### 5.4 디자인 가이드
- 톤: 미니멀, 여백 넉넉히, 카드형 단일 컬럼
- 색상: CSS 변수로 토큰화 (`--bg`, `--surface`, `--text`, `--muted`, `--accent`, `--danger`) → 라이트/다크 두 세트
- 폰트: 시스템 폰트 스택 (`Pretendard`, `-apple-system`, `Segoe UI`, sans-serif)
- 애니메이션: 추가/삭제 시 150~200ms 페이드·슬라이드, `prefers-reduced-motion` 존중

## 6. 기술 설계

### 6.1 기술 스택
| 영역 | 선택 | 이유 |
|---|---|---|
| 마크업 | HTML5 | 단일 페이지 |
| 스타일 | 순수 CSS (CSS 변수) | 의존성 없음, 다크모드 토큰 처리 용이 |
| 로직 | Vanilla JavaScript (ES Modules) | 규모가 작아 프레임워크 불필요, 빌드 없이 실행 |
| 저장소 | `localStorage` | 서버 없이 영속화 |
| 테스트 | Vitest (로직 단위 테스트) | 선택 사항 |

> 확장 시 React/Vue 전환이 가능하도록 **상태(store) ↔ 렌더(view) ↔ 저장(storage)** 를 분리한다.

### 6.2 폴더 구조 (예정)
```
todolist/
├── prd.md              # 본 문서
├── index.html          # 진입점
├── css/
│   └── style.css       # 레이아웃, 테마 토큰
└── js/
    ├── main.js         # 초기화, 이벤트 바인딩
    ├── store.js        # 상태 관리 (todos, filter) + 액션
    ├── storage.js      # localStorage 읽기/쓰기, 스키마 검증
    ├── view.js         # DOM 렌더링
    └── date.js         # 날짜 키 생성, 포맷팅
```

### 6.3 데이터 모델

```ts
// 할 일 하나
interface Todo {
  id: string;          // crypto.randomUUID()
  text: string;        // 1~100자, 앞뒤 공백 제거
  done: boolean;
  important: boolean;  // F-20
  date: string;        // 'YYYY-MM-DD' (로컬 기준, 귀속 날짜)
  createdAt: number;   // epoch ms
  completedAt?: number;
  order: number;       // 정렬용 (F-06)
  carriedFrom?: string; // 이월된 경우 최초 날짜 'YYYY-MM-DD' (F-31)
}

// localStorage 저장 형태 (key: "todolist:v1")
interface AppData {
  version: 1;
  todos: Todo[];
  settings: {
    theme: 'system' | 'light' | 'dark';
    filter: 'all' | 'active' | 'done';
  };
  carryDismissedDate: string | null; // 이월 배너를 '무시'한 날짜 (F-31)
}
```

### 6.4 상태 흐름

```
사용자 이벤트 → main.js (핸들러)
             → store.dispatch(action)   // 순수 함수로 새 상태 계산
             → storage.save(state)      // 즉시 저장
             → view.render(state)       // 화면 갱신
```

**액션 목록**
| 액션 | payload | 설명 |
|---|---|---|
| `ADD_TODO` | `{ text }` | 오늘 날짜로 추가 |
| `TOGGLE_TODO` | `{ id }` | 완료 토글, `completedAt` 갱신 |
| `EDIT_TODO` | `{ id, text }` | 빈 텍스트면 삭제로 처리 |
| `DELETE_TODO` | `{ id }` | 삭제 (실행 취소용으로 직전 항목 보관) |
| `UNDO_DELETE` | – | 마지막 삭제 복원 |
| `CLEAR_DONE` | – | 오늘 날짜의 완료 항목 제거 |
| `TOGGLE_IMPORTANT` | `{ id }` | 중요 표시 토글 |
| `CARRY_OVER` | – | 이전 날짜 미완료 항목의 `date`를 오늘로 변경 |
| `SET_FILTER` | `{ filter }` | 필터 변경 |
| `SET_THEME` | `{ theme }` | 테마 변경 |

### 6.5 핵심 로직 규칙
- **오늘 목록** = `todos.filter(t => t.date === todayKey())`
- **정렬** = 중요(★) 우선 → 미완료 우선 → `order` 오름차순
- **날짜 키**는 `toISOString()`(UTC)이 아닌 **로컬 시간** 기준으로 생성 (자정 부근 오류 방지)
- 페이지가 열린 채 자정을 넘기면 `visibilitychange`/주기 체크로 날짜 갱신
- 저장 데이터 로드 시 `version` 확인 및 필드 검증, 실패 시 백업 키(`todolist:v1:corrupt`)로 옮긴 뒤 빈 상태로 시작

## 7. 수용 기준 (Acceptance Criteria)

- [ ] 할 일을 입력하고 Enter를 누르면 목록 맨 아래에 추가되고 입력창이 비워진다.
- [ ] 공백만 입력하면 아무 일도 일어나지 않는다.
- [ ] 체크박스를 누르면 취소선이 생기고 진행률이 즉시 갱신된다.
- [ ] 삭제 후 5초 안에 "실행 취소"를 누르면 원래 위치로 복원된다.
- [ ] 더블클릭 편집 중 Esc를 누르면 원래 텍스트로 돌아간다.
- [ ] 새로고침 후에도 모든 항목·완료 상태·설정이 유지된다.
- [ ] `<script>` 등 HTML을 입력해도 텍스트 그대로 표시된다.
- [ ] 모바일(360px) 화면에서 가로 스크롤이 생기지 않는다.
- [ ] 마우스 없이 키보드만으로 추가·완료·수정·삭제가 가능하다.
- [ ] (P1) 다음 날 접속 시 미완료 항목 이월 배너가 표시되고, 가져오기 시 오늘 목록에 나타난다.
